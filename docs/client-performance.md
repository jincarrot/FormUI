# 客户端性能优化与复测

本次优化保留公开调用方式和输入轮询频率，重点减少逐帧重复操作、无关数据遍历和布局调用。结果来自离线 SDK 替身测试，不是网易客户端 FPS 或耗时测量。

## 相同场景下的调用次数

| 场景 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 500 个静态文本 + 100 个滑动条，60 个空闲帧：网格检查遍历控件次数 | 36,000 | 0 |
| 同上：滑动条数值文本写入次数 | 6,000 | 0 |
| 修改一个 Group 子文本：该子控件的尺寸/位置写入次数 | 4 | 0 |
| 1000 行 ListView，从已有选项切换到另一项：选中标记可见性写入次数 | 1000 | 2 |

复测命令：

```powershell
python -S -B tools/benchmark_client.py
python -S -B -m unittest discover -s tests
```

基准脚本在同一组场景里统计实际布局遍历和原生方法调用。网格遍历为 0 的场景使用旧顺排布局；启用二维网格时仍逐帧读取相关容器尺寸，以响应窗口、屏幕和 Group 尺寸变化。

## 已落实的优化

- **帧内输入检查**：滑动条保持逐帧读取原生值；原生百分比没变时跳过数值换算，业务数值没变时跳过文本写入和路径查找。加载指示器只在状态变化时修改可见性。输入记录按表单和控件地址索引，更新时不再在列表中反复搜索。
- **网格检查**：创建、追加控件或 Group 重建时生成网格方案；尺寸变化复用方案。逐帧只检查实际使用网格的窗口、内容区和 Group，不再遍历所有控件。相同屏幕尺寸在一帧中只读取一次。
- **Observable 分发**：为序列化绑定、表单、受影响控件和 Custom 参数建立依赖索引。通知只更新对应的绑定引用与控件；等待显示的表单和 Group 注册定义也使用索引。Custom 参数仍按更新顺序保留 old/new 快照。
- **布局触发**：修改文字或普通参数不再触发无关 Group 的布局；移动整个网格窗口不重排内容。尺寸、字体缩放、显隐、Group 模板变化仍按需要重排。旧布局使用缓存的模板尺寸和偏移，消除默认参数表达式引起的额外原生读取。
- **ListView 选择**：建立选项 key 到选中标记的映射，只更新前后两个标记。点击已有行无需重新解包和校验整份 items；仍检查行所属实例，忽略删除行的延迟点击。
- **帧任务队列**：按顺序遍历并保留未完成任务，避免逐条 remove 的列表搜索。任务回调新增的任务从下一帧开始执行。抛出异常也计入执行次数，防止失败任务无限占用后续帧。

索引增加了与绑定数量、网格容器数量和 ListView 行数相关的内存占用。关闭表单、重建 Group、重新注册 Group 定义及重新创建 Screen 时会清除或替换对应引用。普通通知不会重新建立全表索引；结构变化仍有一次性成本。

## 行为与验证边界

输入轮询没有降频，通知没有合并，因此滑动、文本输入、Custom 更新顺序及现有绑定语义保留。轮询使用稳定快照并检查记录是否仍有效，允许输入回调同步关闭表单或重建控件；单个原生输入读取异常不会阻止其他输入更新。

新增回归测试覆盖空闲调用次数、网格方案复用、只处理有关联的表单、绑定别名的旧值、关闭后的缓存清理、Group 重注册、等待创建的 Group 列表数据、同步输入回调、失败任务结束及千行列表选择。

动态表单的 ListView 在首次显示和 items/itemHeight 变化时逐行创建或重建。预编译表单可在原生模板内实例化初始行，之后按列表长度差额增删。两种模式的原生行总量都随条目数增长。窗口和控件初次设置布局时直接写入目标几何值，仅活动窗口的过渡动画读取当前位置或尺寸作为起点。上面的离线数据对应原有动态路径，预编译模式尚无实机帧耗时数据。[预编译表单指南](compiled-forms.md)
